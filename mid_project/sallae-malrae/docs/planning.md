## 문제 정의

**왜 이 문제인가** — 소비자 10명 중 7명이 충동구매를 경험하고, 그중 84.6%가 앞으로는 충동구매를 하지 않으려 노력하겠다고 답했다(뉴시스, 2017). 특히 20대는 충동구매 후 기분이 좋아진다는 인식이 다른 연령대보다 높은 반면, 후회도 가장 많이 하는 세대다. 알면서도 멈추지 못한다. 의지가 없어서가 아니라, 욕구가 생기는 순간 그것을 붙잡아줄 도구가 없기 때문이다.

**타깃 사용자** — 충동구매를 인지하고 있고, 줄이고 싶은 20대.

**핵심 페인포인트**

- 사고 싶다는 욕구가 생기는 순간 바로 결제로 이어진다.
- 충동구매로 인해 예상치 못하게 월말 잔고가 부족해진다.
- 충동구매를 억제할 실질적인 도구가 없다.

## 해결책

충동구매는 "욕구 발생 → 즉시 결제"의 짧은 사이클에서 발생한다. 이 사이클 사이에 쿨다운 기간을 삽입하면 구매 욕구가 자연스럽게 식으면서 불필요한 소비를 막을 수 있다. 행동경제학의 쿨링오프(Cooling-off) 원리를 UX에 녹여, 사용자가 자연스럽게 소비를 재고하도록 유도한다.

"귀찮게 기록까지 해가며 쓸까?"라는 의문에 대해 — 다이어트 앱도 칼로리를 직접 입력하는 게 귀찮지만 살을 빼고 싶은 사람은 쓴다. 충동구매를 줄이고 싶다는 의지가 있는 사람에게 도구를 제공하는 것이고, 등록하는 행위 자체가 "한 번 더 생각해보자"는 첫 번째 억제 장치가 된다.

**한 줄 설명** — "사기 전에 N일만 기다려봐 — 충동적인 당신을 위한 충동구매 브레이크 서비스"

**핵심 가치 제안**

- 욕구가 생겼을 때 등록하는 행위 자체가 첫 번째 억제 장치
- 쿨다운 기간이 지난 후 구매 여부를 다시 결정 — 충동이 아닌 이성적 판단으로
- 참은 횟수와 절약 금액이 누적되어 보이며 성취감 제공
- 카테고리별 충동구매 시각화로 자기 소비 습관 인식
- 이메일 알림과 대시보드 알림

## 차별점

| 기존 서비스 | 한계점 | 살래말래 |
|---|---|---|
| 뱅크샐러드 / 토스 | 소비 후 기록·분석 중심, 구매 억제 기능 없음 | 구매 전 욕구 단계에서 개입 |
| 일반 위시리스트 앱 | 모아두기만 함, 억제 장치 없음 | 쿨링오프 타이머 + 알림으로 실질적 억제 |

## 핵심 기능 (MVP)

**1. 회원가입 / 로그인**

- JWT 인증 (AT 15분 + RT 7일, HttpOnly + SameSite=Strict 쿠키, Rotation)
- 비밀번호 bcrypt 암호화, IP 기반 Rate Limiting

**2. 대시보드**

- 쿨링오프 진행 중 항목과 남은 기간, 만료 항목 알림
- 참은 횟수 / 절약 금액 요약, 짠돌이 레벨(5단계) 표시
- 서버 컴포넌트가 DB 직접 조회 — 별도 API 없이 데이터가 담긴 HTML 전송

**3. 쿨링오프 (핵심 도메인)**

- 항목 등록: 상품명, 가격, 카테고리(6종), 쿨링오프 기간, 메모, 이미지, 충동 지수(1~10)
- 기간 설정: 현재 시각 기준 최소 1시간 이후 ~ 최대 30일, 정각 단위
- 이미지: sharp 리사이즈 + WebP 변환 후 GCS 업로드
- 이메일 알림: 만료 24시간 전 + 만료 시점 (systemd timer 매 정각 실행, DB UNIQUE 제약으로 중복 발송 차단)
- 결정: 살래(구매함) / 말래(아낌) — 상태 변경·통계 누적·레벨 재계산을 한 트랜잭션으로 처리
- 등록 정보 수정 불가(등록 시점의 기록은 불변), 삭제는 대기 중 항목만 가능

**4. 활동 공유**

- 참은 횟수 / 절약 금액 / 카테고리별 패턴 / 레벨 통계
- 공유 토큰 기반 퍼블릭 URL (`/share/:shareToken`) — userId 노출 없이 추측 불가능한 토큰
- 서버 컴포넌트 + `generateMetadata()`로 OG 태그 지원 — SNS 공유 시 미리보기 생성 (Next.js 선택의 핵심 근거)

## 페이지 구조 (7개)

| 경로 | 역할 |
|---|---|
| `/` | 랜딩 (서비스 소개) |
| `/auth/login`, `/auth/signup` | 인증 |
| `/dashboard` | 메인 — 활동 요약 |
| `/coolingoff` | 쿨링오프 항목 목록 (상세는 패널로 처리) |
| `/coolingoff/new` | 항목 등록 |
| `/share/:shareToken` | 공유 결과 (인증 없이 접근 가능) |

## 기술적 어필 포인트

- Next.js API Routes 기반 풀스택 아키텍처 + systemd timer 워커 분리 (ADR-001)
- 행동경제학(쿨링오프) 기반 UX — 단순 기록 앱과의 차별화
- 의도적 쓰기 시점 갱신 설계 — 월별 집계 반정규화 + 레벨 계산값 캐시 (ADR-002)
- 결정 통합 트랜잭션 — 상태 변경 + 통계 UPSERT + 레벨 재계산의 원자적 처리 (ADR-003)
- CHECK / UNIQUE 제약으로 DB 레벨 정합성 방어 (ADR-004)
- JWT 인증 보안 설계 — Refresh Token Rotation, 재사용 감지 시 전 세션 만료 (ADR-005)
- 상태 기반 멱등 API 설계 (ADR-007)
- 설계 의사결정 문서화(ADR) — 대안 비교와 트레이드오프 추적 가능
- 모바일 우선 반응형 설계
