# ADR-0008: 재고 — 모델링 안 함 → 결제 트랜잭션 내 차감 → 옵션 단위 (2회 번복)

- 결정일: 2026-07-06 (미모델링) → 2026-07-17 (모델링+차감) → 2026-08-09 (옵션 단위)
- 상태: 채택 (최종: `product_stock` 테이블, 옵션 단위)
- 근거 문서: `jarvis-backend/docs/backend/02-data-model.md` D8 → D33 (및 2026-08-09 개정)

## 맥락과 결정의 변천

같은 주제를 두 번 번복한 기록이다. 각 시점의 판단은 그 시점의 소비자(consumer) 존재 여부에 근거했다.

### 1차 (07-06): 재고를 모델링하지 않는다

- 소비자가 없고, 품절 상품이 추천되면 핵심 데모 플로우가 깨진다.
- 기각: 아무도 읽지 않는 표시용 `stock` 컬럼(OAuth 컬럼을 지운 것과 같은 YAGNI 논리), 모의 결제 대비 과한 완전 차감.

### 2차 (07-17): 모델링하고, 결제 트랜잭션 안에서 차감한다

소비자가 등장했다 — 판매자 에이전트의 재고 조정(I-11)과 STOCK 변경 로그. 차감 방식:

- **조건부 UPDATE** `SET qty = qty - n WHERE qty >= n`을 **PAID 전이와 같은 트랜잭션**에서 실행. 미결제 주문은 재고를 점유하지 않고, 차감 실패는 결제 실패(`OUT_OF_STOCK`)가 된다.
- 이후 보완(08-05): 주문 생성 전에 재고를 사전 검증해 대부분을 깨끗한 400으로 처리하되, **사전 검증은 경합 창을 좁힐 뿐이며 조건부 UPDATE가 최후의 방어선**임을 명문화.
- 취소·반품 시 복원은 MVP 미구현으로 미뤘다가 08-10 추가.

### 3차 (08-09): 상품 단위 → 옵션 단위 (`product_stock` 테이블)

측정이 방아쇠였다 — 카탈로그의 **29.2%**(1,921/6,585)가 복수 색상 보유. "빨강만 품절"을 표현할 수 없어 AI가 품절 옵션을 추천하는 문제.

- `(product_id, option_id)` 키의 전용 테이블. 옵션 없는 상품은 `option_id NULL` 행 1개. 상품 레벨 컬럼은 **삭제**.
- 기각 3안과 사유: (a) 상품 테이블에 합계 유지 — 같은 사실이 두 곳에 있으면 **오류 없이 조용히 어긋난다** (평점 비정규화를 거부한 D9와 같은 판단) (b) "옵션 있으면 옵션 재고, 없으면 상품 재고" — 컬럼이 어떤 상품에는 진짜, 어떤 상품에는 가짜가 되어 모든 읽기 지점에 분기를 강제 (c) `product_option`에 재고 컬럼 — 그 테이블은 "표시할 선택지"라서 옵션 없는 상품에 유령 "기본" 행이 생기고 주문 내역에 인쇄됨.
- 시드 재고도 일괄 100에서 **옵션 id 기반 결정적 파생(일부 0 포함)**으로 변경 — 품절이 하나도 없으면 기능을 검증할 수 없고, 랜덤이면 시드마다 화면이 달라진다.

## 트레이드오프·결과

- 최대 비용은 계약 파급 — I-11 입력이 배열이 되어 판매자 챗봇도 함께 변경.
- 관련 동시성 보강(07-18 전수조사): 판매자의 절대값 재고 수정과 주문의 조건부 차감이 경합해 판매분이 유령 복원되는 경로를 쓰기 락으로 차단.
- "번복"이 실패가 아니라 방법론이었다: 결정마다 번복 조건(소비자 등장, 측정 결과)을 미리 적어뒀고, 그 조건이 충족되자 뒤집었다.
