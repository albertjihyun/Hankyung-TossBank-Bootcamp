# ADR-0011: 캐시는 측정 후에 — 부하테스트가 뒤집은 "캐시 불필요" 판정

- 결정일: 2026-08-10
- 상태: 채택 (캐시 대상 2종 → 5종)
- 근거 문서: `jarvis-backend/docs/backend/07-redis-design.md` §3-1, `README.md` 기술 챌린지; `docs/load-testing.md` (이 저장소)

## 맥락

부하테스트(4대 t3.small, `docs/load-testing.md`)에서 RDS CPU 94% 포화 + 커넥션 28개(4대 × 풀 7) 전부 소진이 측정됐다. 이전까지 캐시 대상 선정 기준은 "이 쿼리가 느린가"였고, 그 기준으로 리뷰 통계는 "커버링 인덱스면 충분, 캐시는 최후 수단"으로 **캐시 제외** 판정을 받은 상태였다.

## 결정

선정 기준을 **"많은 사람이 같은 계산을 반복하는가"**로 다시 세우고, 캐시를 2종에서 5종으로 확장한다: 인기 상품, 카테고리 트리, 리뷰 통계, 브랜드명, 상품 상세 정적 조각.

**번복 2건을 명시적으로 기록:**

- **리뷰 통계 제외 판정 번복** — 원래 추론은 쿼리 *속도*에 대해서는 옳았지만 병목은 그게 아니었다. 병목은 RDS CPU 총량과 커넥션 점유였고, 빠른 쿼리도 초당 수백 번 돌면 CPU를 채운다.
- **무효화 부채 과대평가 번복** — 쓰기 지점이 한 곳뿐이었고, 비정규화 컬럼과 달리 **TTL이 어긋남의 상한을 보장**한다 (파생값 저장을 거부한 D9 원칙의 보강이지 위반이 아님).

**인기 상품은 ID가 아니라 조립된 카드 전체를 캐시** — ID만 캐시하면 히트여도 하이드레이션 쿼리 4개가 나가 DB 보호가 절반에 그친다. 대가는 홈 카드의 가격·품절이 최대 3분 낡을 수 있음인데, 홈 카드에는 담기·결제 경로가 없어 수용.

## 영구 제외와 사유

- **장바구니·주문·재고** — "틀리면 돈이 틀린다". 이미 조건부 UPDATE와 비관적 락으로 해결된 영역이고 캐시가 낄 자리가 아니다.
- **검색 결과** — 재사용이 없다.
- **판매자 지표** — 반복 조회가 없고, 자기 수정이 즉시 보여야 한다.

## 구현 불변식 (`global/cache/RedisCache`로 중앙화)

1. 무효화는 **커밋 후에** (evict after commit)
2. 스탬피드 방지는 SETNX + "직접 계산" 폴백 — 중복 계산이 무한 대기보다 낫다
3. 읽기는 **fail-open** — 캐시 장애가 서비스 장애가 되지 않게

## 결과

같은 스크립트로 전후 측정: **처리량 +31%, p95 지연 −26%**. 병목 이동 서사(앱 CPU → DB CPU → 커넥션 수)의 마지막 단계.
